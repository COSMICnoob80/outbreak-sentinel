## 1. Track fit — Apps & Agents (Track 01), score 5/10

**Does the repo serve the track?** Partly. Section 5 requires: *“at least one
genuinely autonomous machine-to-machine purchase or sale using the supported
Telegraph flow, then use the intelligence to perform a meaningful task.”*

- **Verified purchase leg.** `POST /telegraph/risk` → `TelegraphClient.buy_intelligence`
  → live 402 challenge on `eip155:84532` → EIP-3009 settlement. `GET /telegraph/status`
  on the live instance returns `is_live: true`, `chain_id: 84532`,
  `settlement_mode: live`, and a testnet-boundary string. On-chain:
  - `0x979515ea…7067` — block **61,335,917**, USDC `Transfer` **10,000 units
    (0.01 USDC)** from burner `0x7b36…f249`.
  - `0xac02bcbb…c4cf` — block **59,597,289**, 10,000 units, same burner.
  - `0xf2276f58…97d4` — block 48,374,650, 10,000 units, same burner (routed via
    Multicall3 `0xca11…ca11`, but the USDC `Transfer` log is present).
  All three are real Base Sepolia transactions. **This is the strongest part of
  the entry.**
- **Failure: the second half of the requirement.** In `app.py:1283–1310` the
  paid `proof` is obtained, then the risk card is built independently by
  `collect_signals()` from free Google News RSS + Open-Meteo. The only use of
  `ranked_answer` is to echo it in JSON (`app.py:1398`) and dump it raw in
  `static/telegraph.html:119`. The card’s level, score, drivers and sources are
  identical whether the purchase succeeds or fails. A judge reading the code can
  falsify “buys intelligence, then uses it” in two minutes.
- **Intent quality.** `telegraph/client.py:46` sets
  `DEFAULT_DISCOVERY_INTENT = "SENTIMENT_ANALYSIS"` — a generic intent that has
  no relationship to wildfire, supply-chain or outbreak drivers. The mission
  pages explicitly expect domain intents (`WEATHER_FORECAST_VERIFY`,
  `LIVE_PORT_CONGESTION`, `ROUTE_ETA`, `SENSOR_TELEMETRY_VERIFY`). The purchase
  is real but the intelligence is not mission-shaped.

## 4. Submission gap list (ranked)

### BLOCKING

1. **Submission still points at localhost/tailnet.** `demo/HACKATHON-SUBMISSION.md:11–15`
   says “No public deployment is claimed” and gives `127.0.0.1:8001` plus
   `http://100.82.76.91:8001` (tailnet-only). The verified live URL exists but
   is absent. A reviewer cannot run the entry.
2. **No demo video.** Rules Section 8 require a 2–5 minute video (“or accessible
   equivalent”) showing real input, result and Telegraph integration. The repo
   has scripts (`SCRIPT-60s.md`, `SHOTLIST.md`, `VOICEOVER.txt`) and zero media
   files. `demo/RECORDING.md` describes how to record, not a recording.
3. **Receipt ledger is dead on the deployed instance.** `publish_cards` is never
   called, and `.dockerignore` excludes `history/receipts.jsonl`. `/scoreboard`
   = 0. The one differentiator the pitch repeats is unobservable.
4. **Paid intelligence does not drive the card.** Section 5’s “then use the
   intelligence to perform a meaningful task” is not satisfied in code. Either
   use `ranked_answer` as a cited driver / corroborating signal, or state plainly
   that the payment notarises the assessment rather than shaping it.
5. **Mission selection is absent and the track is mislabelled.** No submission
   field names 1–2 missions; `pitch/HACKATHON-FIT.md` invents missions 05/06/08
   with the wrong rubric. Pick **06 (days-to-impact)** and/or **11 (autonomous
   forestry buying fire-risk)**, buy the matching intents, and label the entry
   **Track 01 — Apps & Agents**.

### HIGH

6. **Settlement proof disappears on restart.** `/telegraph/status`
   `last_settlement: null`; the dashboard shows “0 / none yet”. Read the latest
   row from `state/settlements.jsonl` (already persisted) and seed the strip +
   tx link from it on page load. Also surface the burner balance from a
   configured payer address instead of `last_proof`.
7. **The 60-second script’s hero beat is not reproducible.** It promises Karachi
   dengue HIGH and block 48,410,853. Today Karachi is LOW/20 and the live tx is
   block 61,335,917. Refilm around the wildfire HIGH card and the new tx.
8. **`state/hackathon-state.md` is dangerously stale.** Wrong primary target,
   wrong deadline (Oct 28), wrong settlements. It calls itself the single source
   of truth. Rewrite or delete.
9. **Narrative claim cleanup.** “1 cent notarises every prediction”, “free Groq
   fusion”, “7 verticals ship”, “we are cut on Nov 14”, “Track 03”. Each is a
   two-minute falsification for a judge.
10. **Supply-chain vertical reads as broken.** 14 empty LOW cards. Either loosen
    the vocabulary with evidence, or default the demo filter to wildfire and
    present supply-chain as an honest empty state.

### NICE

11. Wallet balance on the console (`wallet: —`) — derive from a configured
    payer address, not `last_proof`.
12. Old ledger row says `engine: rule-based` and “35 articles in 24h”, which
    contradicts the current 7-day density engine. Label historical rows.
13. No screenshots anywhere (`find . -iname "*.png"` → none). Submission form
    and README would benefit.
14. Organic-growth points (20 of 100) have no dated public updates, tutorial or
    independent reproduction. Zero evidence today.
15. Star the bounties repo and record the GitHub username — required by rules
    Section 5, item 06.
